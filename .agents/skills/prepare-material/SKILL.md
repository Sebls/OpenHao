description: Prepare selected physical PDF pages for this repository's offline Chinese study library, add pages without changing accepted content, or repair an exact copied item reference.
---

Use from the repository root. Read `AGENTS.md`, `docs/interactive-reader/current-requirements.md`, `docs/interactive-reader/content-contract.md`, and `config/learning-profile.json`. The implementation guide is `docs/interactive-reader/implementation.md`.

Prepare only requested physical pages. If missing, ask for the page selection; do not silently process the whole PDF. Reuse English beginner teaching, Mandarin tone-mark pinyin, separately labeled reviewed IPA, and sparse source-first examples. A request to prepare pages includes routine agent review, validation and local publication. Do not request routine stage approvals or upload PDFs.

## New source or later pages

1. If `.venv/bin/python` cannot import `pymupdf`, run `npm run setup:extractor`. This dependency is needed for preparation only; studying needs Node alone.
2. `npm run content:inspect -- --input "/absolute/source.pdf"` reports metadata and hash without page extraction. Match an existing document by source SHA-256, not a similar lesson title or filename; otherwise choose a new stable ID.
3. `npm run content:extract -- --input "/absolute/source.pdf" --id "stable-id" --pages "1,3-4"`. For an existing document use `--id "stable-id" --pages "3"`. Full-document preparation requires explicit `--all-pages`. Ready requested pages skip without a revision. Originals are copied once to `data/pdfs`; never edit them.
4. Read `data/staging/<id>/pages/pNNNN/text.txt` and `layout.json`; inspect `source.png` visually. The transcript uses Unicode code-point offsets, not JavaScript string indices. Raw MuPDF character geometry is genuine, normalized to the rotated visible CropBox. Do not divide line boxes to invent characters. Classify line roles; compare illustration labels, decorative text, punctuation and reading order. For scans, mixed French/Chinese spreads, missing handwriting, or an OCR failure, read `docs/interactive-reader/scanned-source-preparation.md` before choosing OCR or repairing an unpublished extraction. It covers Tesseract and the optional local macOS Vision engine, skipped staged pages, and manual character alignment. Never claim an empty embedded extraction is complete. Stop only the affected page if reliable anchors cannot be made.
5. Author `entries.json`, `annotations.json`, `questions.json`, `review.json` using the content contract and `schemas/page.schema.json`; every file repeats documentId/pageId/extractionRevision. Record English contextual `meaning`, concise `explanation`, `pronunciations: [{system:"pinyin",value:"nǐ hǎo",language:"zh-CN",reviewStatus:"reviewed"}, {system:"ipa",value:"[ni³⁵ xɑʊ²¹⁴]",...}]`, optional `grammar`, `constituentIds`, Chinese `speechTarget`, provenance, and reviewStatus. Omit uncertain IPA and report it. Entry `form` stays distinct from meanings; names are names, not literal translations.
6. Each occurrence has a stable unique ID, entryId, kind and exact anchored start/end/characterIds. Repeated words have separate IDs. Derive offsets and geometry from the extraction, never a global runtime text search. A form differing from the source requires an explicit `formMapping`. Keep uncertain items `needs-review` and exclude their questions. Review polyphonic characters, contextual tones, neutral syllables, name/title order, respectful pronouns, and natural sentence translations.
7. Author supported single-choice categories where defensible: meaning in both directions, character identification, sentence comprehension, missing word, grammar and listening. Use stable option IDs, one defensible correct option, explanation, sourceAnnotationIds, requiresAudio, origin and reviewStatus. Listening adds speechTarget and is gated by successful local playback. All question sources must be within the selected scope; do not create filler or equivalent correct answers. Put pageId in each question for correction references.
8. Run a **separate** source/linguistic/question review pass. `review.json` requires matching textSha256, sourceVisualReview, linguisticReview, reviewer, checks, coverage and issues with severity/reason/nextAction. Do not claim human or independent review. Define coverage by counts and source role. Isolate decorative/transcription uncertainty explicitly. French-only instruction/cover pages may remain `extracted` as reviewed reference-only pages: record why, leave the question bank empty, and report that the current UI labels them “Not prepared.” Do not invent Chinese entries or pinyin to satisfy readiness. Set only usable reviewed pages to `ready` in staged `manifest.json`; leave unrequested pages unchanged. Never edit accepted earlier page files during additions.
9. `npm run content:diagnose -- --id ID --page 1` emits a source-linked SVG showing real character boxes. Regenerate diagnostics after the final text/geometry edits; inspect at multiple sizes, plus the app overlay for character, word and any available multiline anchors. If a unit type is absent, record it as not applicable. Complete the separate linguistic/question review before the first publication; if browser review then finds an explanation error, use scoped item repair and validate/publish again. Remove scratch diagnostics only from staging if unnecessary. `npm run content:validate -- --id ID`, then `npm run content:publish -- --id ID`. Publication recalculates hashes, validates, checks the staged base revision and untouched pages, retains old revisions and atomically changes a small current pointer. A stale-base conflict needs a deliberate rebase, never a forced overwrite.
10. `npm run content:list` confirms discovery. Report added/skipped physical pages and unresolved exceptions briefly. Study requires no AI or network.

## Command fallback

If an npm content command fails with a `tsx` IPC-pipe `listen EPERM` error, use the same arguments with `node --import tsx src/content/cli.ts <command>`; for example, `node --import tsx src/content/cli.ts validate --id ID`. This avoids the CLI IPC listener without weakening execution permissions. It does not bypass a genuine filesystem or network restriction.

## Targeted correction

`npm run content:lookup -- --ref "ID:p0001:annotation:ITEM@r1"` resolves the exact stable item, source context, current revision and dependent questions. `npm run content:repair -- --ref REF` stages the current package and records the authorized page/item repair scope. Edit that item and review affected questions, preserving IDs and unrelated records. Do not change source text or geometry to fix an explanation. Update review evidence, validate and publish. Source/extraction repairs need an explicitly requested migration with a new page extraction revision and remapped dependencies; ordinary item repair cannot change frozen extraction. Never silently retire or reassign an item ID.
